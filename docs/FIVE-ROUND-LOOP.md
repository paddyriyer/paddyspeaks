# The Five-Round Loop (`/interview.app/loop/`)

A complete senior data engineering interview loop in the Interview Studio. It has
five rounds of five questions, in three modes:

| Round | Focus |
|---|---|
| 1 | SQL & data structures and algorithms (sliding windows, gaps-and-islands, sessionization, query optimisation) |
| 2 | DSA & core data engineering (bitmask game DP, interval DP, delivery semantics, CDC, a PySpark debugging exercise) |
| 3 | Data modeling & low-level design (seat booking, trip lifecycle, food delivery, payments ledger, subscriptions) |
| 4 | Distributed systems & high-level design (video streaming analytics with five live challenges, surge features, courier tracking, right-to-be-forgotten, experimentation metrics) |
| 5 | Leadership & architecture (trade-offs, cost, technical debt, incidents, conflict) |

- **Practice**: one question at a time. Run and check SQL or Python, reveal the
  reference solution, then score yourself against it.
- **Mock interview**: one question at a time, with a clock against the estimate.
  Clarifying questions are hints, shown only on request. Live challenges and
  follow-ups arrive one by one, after the candidate answers.
- **Assessment**: one countdown for the selected questions, and the solutions stay
  hidden until submission. Then the candidate scores each answer and gets a report:
  round by round, by competency and by topic, plus strengths and weaknesses, what
  was incorrect or incomplete, topics to revisit, three targeted follow-up practice
  questions (the first follow-up of the three weakest answers) and specific
  recommendations.

Scores are **self-scores** on a 0–4 rubric per competency. Each question names the
competencies it tests, and the rest are N/A, never 0. The page never pretends to
grade free text. The optional AI interviewer uses the visitor's own Anthropic key,
stored by `/interview.app/mock-ai/` (`ps-mock-key`, `ps-mock-model`). It sends the
question, the answer and the reference notes from the browser to Anthropic.

## Rules

1. **Original practice problems.** Never call a question real, verbatim, reported or
   asked by a named company, and never name a company as a question's "style".
   `build.py` fails on "Uber-style" and friends and on "asked at", "verbatim", "real
   interview question". "RideCo" and "StreamCo" are invented, and scenario numbers are
   marked *scenario assumption*.
2. **Never type an expected output.** Every sample output in `questions.md` and every
   value in `expected.json` comes from running the reference solution: Python 3, and
   PostgreSQL 16 for SQL. To change an example, change the data or the test, then
   re-run:
   ```
   python3 interview/loop/verify/compute_expected.py   # needs psql + a PostgreSQL (PGHOST/PGPORT/PGUSER)
   python3 interview/loop/build.py
   ```
   CI re-checks the Python results (`--python --check`) and the random cross-checks
   (`algos.py`). The SQL results can only be re-checked where a PostgreSQL exists, so
   run the full script locally when you touch any `.sql` file.
3. **The candidate file never carries evaluator text.** `solutions.json` is fetched
   only when a solution is revealed or a mock or assessment ends. `build.py` fails if
   evaluator markers appear in `questions.json`. Both files are public URLs, so this
   is hiding, not secrecy.
4. **Diagnostics are known wrong answers.** Each one (in `runners.py`) carries the
   message the candidate sees when their result equals it. `compute_expected.py`
   fails if a diagnostic ever equals the expected result.
5. **Timing tests must separate the intended complexity from the naive one.** The
   R1-01 and R1-02 timing inputs are sized so an O(n·window) or O(n·L) answer is
   stopped, while the reference finishes in well under a second.
6. **One rubric.** The competencies and their labels are in `build.py`
   (`COMPETENCIES`); each question's metadata table names its own. The report's
   advice per competency lives in `loop.js` (`ADVICE`).
7. **Storage.** One key, `ps.loop.v1`, registered in `data/platform/state-keys.json`.
   The page emits no custom analytics events: the Worker's event allowlist is a
   production change (`docs/CHANGE-SAFETY.md`).

## Editing a question

Keep the `## Rn-0k: Title` heading, the metadata table (including **Competencies**)
and the bold section labels that `build.py` reads: Business Scenario, Problem
Statement, Sample Input / Schema, Expected Output, Constraints, Clarification
questions to consider, Live challenges, Interviewer Follow-Up Questions, Evaluation
Criteria. Follow-ups are a numbered list; the mock interview reveals them one item
at a time. Text between `# ROUND n:` and its first question is the round's note.
